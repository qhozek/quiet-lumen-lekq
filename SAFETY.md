# herokusafe — что поменяно и почему

## Обновление 2.2.0 (2026-10-17)

Перенесён снимок `Heroku-userbot/Heroku@19f4a8f82159497d2f67e1fcbea8cab4249b3346`.
Это не автоматическая синхронизация с оригиналом. Исторические заметки ниже описывают 2.1.0;
настройки `Loader.autoupdate_modules` в 2.2.0 больше нет.

### Перенесено

- Rich messages, несколько префиксов, улучшения алиасов, терминала и grep.
- Исправления авторизации, inline lifecycle, `inline_ready`, отмена задач при выгрузке.
- Маскирование секретов, атомарная запись приватных файлов, HTTPS-загрузка, ограничение basic auth.
- Проверка приватности служебных чатов, вложенные сохраняемые указатели, улучшения переводов и логов.
- Кеш установленных модулей и предложение обновить изменившийся код.
- HerokuTL ровно 2.2.0. Это внешний пакет; фиксация версии не заменяет аудит зависимости.

### Не перенесено / ужесточено

- Удалены обращения к `heroku_white`, allow-list и веточная политика с reset/logout.
- Внешние анонсы и предложение вступить в поддержку по-прежнему отключены.
- Ядро проверяет **реальный Git origin**, а не только значение `GIT_ORIGIN_URL`.
  Разрешён только `https://github.com/qhozek/quiet-lumen-lekq[.git]`, ветка `master`.
  Обновление использует фиксированный адрес, запрещает HTTP-перенаправления и только fast-forward;
  локальные изменения не сбрасываются. Чужой origin надо изменить вручную, ничего не переименовывается молча.
- Сохранённый `GIT_ORIGIN_URL` мигрирует на этот форк. Автообновление ядра выключено по умолчанию.
- URL-модули загружаются из `.modules_cache/<account-id>/` без сетевого bootstrap при отсутствии копии.
  Нет копии — запись остаётся в инвентаре, в логах просьба переустановить через `.dlmod`.
  Старый общий download-cache не считается одобренной установленной копией.
- Изменение модуля требует подтверждения; старые `always_update_modules` игнорируются.
  Оригинальный механизм замены кеша «core»-модулей без подтверждения удалён.
- `import_lib` фиксирует копию в `.libraries_cache/<account-id>/`; повторный импорт не скачивает её заново.
  `refresh=True` явно разрешает обновление вызывающему модулю. Это **не sandbox** для злонамеренного модуля.
- API limiter включён по умолчанию, запреты вступления применяются в `client_ready`.
- Сторонние пресеты удалены. Установка по умолчанию клонирует этот форк, не оригинал.
- Docker использует `COPY` текущего checkout; данные в `/data`, код в `/opt/HerokuSafe`.
  Внутренний Git updater выключен, обновление — пересборкой образа. Чужой docker-deploy workflow не переносится.

### Доставка обновления

Старая 2.1.0 уже опрашивает свой `origin`. После публикации коммита уведомление появится
у онлайн-установок, у которых origin указывает на этот форк и уведомления не отключены.
Нельзя гарантировать доставку выключенным ботам, установкам с `--no-git`, отключёнными уведомлениями
или origin оригинала. Для них нужна ручная миграция по README. Не возвращайте внешний broadcast ради доставки.

Сессии и сервер всё ещё доступны установленным модулям. При краже сессии завершайте её в Telegram:
изменение кода не отзывает уже украденный ключ авторизации. Права 0600/0700 — POSIX; в Windows нужны ACL.

## История защиты 2.1.0

Скопия `coddrago/Heroku` без `.git` (оторвана от апстрима, `git remote` чужого нет).
Смысл патчей: чужой пуш / чужая ссылка не должны **молча** выполняться у тебя.
От уже украденной сессии и от модуля, который ты **сам руками** поставил, код не спасет —
для этого чеклист ниже.

## Патчи

1. `heroku/main.py` — `_main()`, `amain_wrapper()`
   Было: при каждом старте декодировался скрытый URL
   `raw.githubusercontent.com/coddrago/modules-web/.../allowed_ids.txt`,
   юзербот ходил туда по сети и тащил список id.
   Стало: phone-home вырезан полностью, `amain_wrapper(client)` без сетевых запросов.

2. `heroku/modules/updater.py` — `poller_announcement()`
   Было: каждые 60 сек тянул `coddrago/assets .../announcment.txt` и слал его
   тебе в личку через инлайн-бота (чужой текст у тебя в акке).
   Стало: `autostart=False` + `return`, но-оп.

3. `heroku/modules/loader.py` — `_update_modules()` + новый конфиг `autoupdate_modules`
   Было: на **каждый рестарт** молча перекачивал ВСЕ внешние модули
   (`download_and_install(mod)` для каждого из `loaded_modules`).
   Чужой пуш в modules-репо = RCE после рестарта.
   Стало: новый `ConfigValue("autoupdate_modules", False)`.
   По умолчанию перекачки нет, только лог. Обновление — руками через `.dlmod`
   или `.config Loader autoupdate_modules=True`.

4. `heroku/modules/api_protection.py` — `client_ready()`, `disable_protection`
   Было: `disable_protection` default `True` (= защита ВЫКЛ), а
   `forbid_constructors(joinChannel/importChatInvite)` применялся только
   после ручной смены конфига. Модуль мог молча джойнить чаты.
   Стало: default `False` (= защита ВКЛ), запрет применяется сразу в `client_ready()`.

5. `heroku/modules/quickstart.py` — `client_ready()`
   Было: `request_join("heroku_talks", ...)` при старте.
   Стало: no-op, только лог. Вступай руками, если надо.

## Что НЕ закрыто (важно)

- `.dlmod <url>`, `.loadmod` (файлом), `.presets` — это произвольный Python,
  он всегда имеет полный доступ к сессии. Ставь только свое/проверенное.
  Пресеты в `heroku/modules/presets.py` (`PRESETS`) ссылаются на
  `mods.codrago.life`, `mods.kok.gay`, `github.com/amm1edev/...` — чужие хосты.
- Если сессия уже ушла раньше (файл `sessions/heroku-*.session`,
  `StringSession.save()`, `config.json`, `bot_token`), патчи не помогут —
  у атакующего независимый клиент. Надо убить сессии (см. ниже).
- Если его id уже в owners/sgroups/tsec — он управляет твоим ботом сообщениями.
  Проверь `.ownerlist`, `.sgroups`.

## Чеклист после копирования

1. Telegram > Настройки > Устройства — завершить чужие сессии.
2. BotFather — `/revoke` для инлайн-бота, 2FA/облачный пароль — сменить.
3. Старт с чистого: новые `config.json`, `sessions/`, не тащить старые
   `config-*.json` / `loaded_modules` вслепую.
4. `git init`, свой remote, в `.config Updater` → `GIT_ORIGIN_URL` на свой форк,
   `autoupdate=False`. В `.config Loader` проверь `MODULES_REPO` / `ADDITIONAL_REPOS`.
5. Первый рестарт при подозрениях: `.restart --secure-boot` (без внешних модулей),
   дальше `.unloadmod` / `.clearmodules`, чистка `.ownerlist` / `.sgroups`.
6. `.api_fw_protection` должен быть ON (теперь по умолчанию, проверь).
